# 共同取景摄像机 · Group Framing Camera

多角色共同取景演示：给定若干活动角色的三维范围和重要性，求出相机位置、朝向与**受限**视场角，把整个身体范围（不是模型中心）放进屏幕安全区。约束无法同时满足时，镜头不越界扩张，而是在结果区报告取舍。

## 如何启动界面

```bash
npm install
npm run dev
```

然后在浏览器打开终端里打印的地址（默认 <http://127.0.0.1:5173/>）。

- 生产构建：`npm run build`，`npm run preview` 预览（<http://127.0.0.1:4173/>）。
- 单元测试：`npm test`（Vitest，内核不变量、随机场景与发行验收规则）。
- 端到端测试：`npm run test:e2e`（Playwright，真实 UI 拖拽 / 边距 / 画幅 / 播放 / 取舍 / 重放 / 重新取景 / 目标边界）。
- 镜头演示发布验收：`npm run release` 或 `npm run release:clean`（净目录），详见下文。

## 界面怎么用

| 区域 | 作用 |
| --- | --- |
| 顶部场景 / 画幅 | 切换 5 个演示场景（含「部署验收 · 分散与聚合」），或 16:9、9:16、21:9、4:3 画幅。画幅会改变投影范围，取景随之重解。 |
| 中央取景窗口 | WebGL 画面 + 真实投影覆盖层。虚线蓝框是安全区，彩色框是每个角色的真实身体包围框，右侧红色斜纹是越界部分。画框按所选画幅加黑边，不会被拉伸。可直接**拖动角色**。 |
| 约束面板 | 偏航、工作镜头、垂直/水平视场上限、距离上限、四向安全边距。全部由取景内核驱动，改动即重解。 |
| 演示节拍 | 播放 / 重放 / 还原，逐段切换；播放中相机与角色连续插值。 |
| 结果面板 | 状态（完全入画 / 约束取舍）、**目标边界（全部角色包络并集，NDC 与画幅占比）**、相机位置朝向、实际视场、距离、相机高度、所需视场；取舍时给出原因与受影响角色，并可一键套用建议。 |
| 重新共同取景按钮 | 「结果」面板内的图形入口，对当前角色与约束重新执行同一求解内核，与拖动 / 边距 / 播放共用 `solveNow()`，不会与实时解算分叉。 |
| 俯视平面 | 世界 +Z 向上的机位、视锥与角色分布。 |
| 复制可重放链接 | 把角色位置、约束、画幅与当前节拍编码进 URL hash，重新打开即复原同一画面。 |

**图形入口是共同取景的主路径**：界面按钮、拖动、滑杆与播放都调用同一个控制器；命令行工具（见下）仅用于辅助（构建、启动、无头核对），不能替代图形入口的验收。

## 取景内核

`src/framing/` 是与渲染无关的纯计算内核：

1. **身体包络采样**（`sampling.ts`）：沿胶囊体表面取环向 / 方位 / 两极采样点，包围框由这些真实表面点投影得到，中心点并不参与判定。
2. **透视投影**（`projection.ts`）：把采样点变换到相机空间并投到 NDC，与 Three.js 的 `PerspectiveCamera` 基向量保持一致。
3. **逐边所需视场**（`evaluate.ts`）：对每个采样点按所在半轴选出需要的安全边，闭式求出恰好贴边的最小垂直 / 水平视场；水平需求再折算成同画幅下的垂直当量。
4. **有效上限**（`caps.ts`）：垂直上限与"水平上限在当画幅下的垂直当量"取较小值，作为硬上限。
5. **姿态搜索**（`solver.ts`）：偏航由用户给定，对横向偏移、机位高度、俯仰做坐标下降；距离不是搜索维度，而是在每个姿态下用粗扫 + 二分求出满足工作镜头的最远 / 最近可行距离。
6. **镜头策略**：工作镜头够用 → 收紧到该姿态的最小所需视场（`working`）；不够 → 在距离上限处放宽到硬上限（`widened`）；仍不够 → 保持硬上限与距离上限，按重要性做取舍（`tradeoff`）。
7. **取舍选择**：字典序——先最大化完整入画的角色重要性总和，再线性分摊不可避免的越界，最后让机位靠近群体轴线，并沿相机右轴做粗扫以免错过关键机位。
8. **连续性**：用上一帧姿态作搜索种子，并加入姿态连续性代价，播放时不会瞬移。

硬约束（视场上限、距离范围、机位高度下限）永远不会被突破；最终镜头再按**密集采样**的安全区需求精确复核，因此不会出现"求解通过、报告越界"的假象。

## 场景与测试覆盖

- `高低平台`（plaza）：两个平台高差 0.55 / 1.15 m，第三人在地面；检验高差、俯仰与机位下限。
- `前后纵深错位`（stagger）：近、中、远景深度差大，近景占屏远大于远景。
- `横向分散 · 受限镜头`（wide-spread）：视场 34°、水平 52°、距离 15 m 三重收紧，三人横向分散到无法同时入画——预期得到显式取舍。
- `双人对白 · 竖屏`（two-shot）：竖屏下水平方向先触顶，验证画幅对取景的影响。
- `部署验收 · 分散与聚合`（deployment）：四名体型不同的角色（高个 2.04 m / 宽体 0.46 m 半径 / 瘦高 1.88 m / 矮个 1.42 m）先聚合、再横向与纵深分散、最后重新聚拢；同一套受限镜头聚合时完整入画、分散时给出显式取舍，用于部署验收。

单元测试覆盖：包络采样、投影符号、双人入画、全部采样点位于安全区、取舍不越上限、连续性；另有 60 个随机场景的不变量测试（有限值、视场落在区间内、距离/机位边界、`fitted ⇒ 全部入画且无身后点`、`tradeoff ⇒ 必有说明`）与性能上限。发行验收规则（缺角色失败、体型差距、视场/屏幕范围、目标边界与安全区对应、失败不采纳产物）见 `tests/release-policy.test.ts`。

端到端测试覆盖真实 UI：拖动、边距、画幅、播放连续性、取舍、重放、重新取景按钮、目标边界读数，以及部署场景的「聚合 → 分散 → 聚合」。

## 镜头演示发布 · 运行配置与验收

镜头演示发布落到运行配置 `tools/release/config.json`（发行编号、启动方式、图形入口选择器、场景、必需角色、体型差距、目标屏幕范围、视场限制、距离上限、边距改动、旧样例清单、产物采纳策略）。验收**读取目标屏幕范围与视场限制**，并在真实浏览器里执行控制器：

- **不使用预设机位视频**：验收由 `tools/release/run-release.ts` 驱动构建后的真实界面（点击重新取景按钮、拖动滑杆、画布内拖动多名角色、播放节拍），所有数字都从运行中的控制器（`window.framingDemo`）与渲染后的舞台读回。控制器没跑就判失败，绝不回退到录制画面。
- **缺角色数据即失败**：`requiredActors` 中的角色缺失、或角色为空，验收直接失败。
- **不同体型检查**：身高与半径的差距必须达到 `bodySize` 下限，避免用同一模板冒充多名角色。
- **屏幕安全区与视场**：读取安全区在屏幕归一化坐标中的范围（`targetScreenRange`），并把每个角色标注的「在框内 / 越界」与其在屏幕上的真实包围框对齐（`targetInsideSafeTolerancePx`）；视场与距离必须落在 `fovLimits` 与 `distanceMax` 之内。
- **旧样例运行到底**：四个旧场景逐段执行到末段并保持已解算。
- **失败禁止采纳**：`shouldAdoptArtifact` 要求全部检查通过才允许采纳构建；任一项失败即 `RELEASE FAIL`，禁止采用产物。

```bash
# 在净目录（临时副本，排除 node_modules/dist/evidence 等）执行整套发行验收
npm run release:clean

# 在当前工作树执行，证据写入 evidence/
npm run release

# 仅辅助：无头求解并打印与界面一致的数字（不渲染、不作为验收）
npm run frame -- --scenario deployment --beat 1
```

证据产物：`evidence/evidence.json`（原始记录）、`evidence/evidence.md`（人读表）、`evidence/shots/*.png`（真实界面截图）、`evidence/dispersed-state.json`（分散态相机 / 安全区 / 角色原始数据）。原始记录里写有执行目录模式与源码修订号（`provenance`），净目录执行可回溯到具体提交。`run-in-clean-dir.sh` 用 `git archive` 从已提交的修订生成临时副本（不依赖本地构建残留），把证据写在净目录并打印路径；仓库中的 `evidence/` 即由该净目录运行产生。

```

src/app/           场景、约束覆盖与快照、Three.js 舞台、覆盖层、俯视平面、UI 状态机
tests/             内核单元测试、不变量测试与发行验收规则测试
tests/e2e/         Playwright 端到端测试（真实 UI）
tools/release/     镜头演示发布：运行配置、GUI 验收运行器、净目录脚本、辅助 CLI
tools/shot.mjs     本地截图脚本（开发辅助）
```
